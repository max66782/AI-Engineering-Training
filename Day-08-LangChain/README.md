# 1. What is LangChain?

LangChain is a framework for building applications powered by Large Language Models (LLMs).

An LLM API gives direct access to a model.

For example:

    Python Application
          ↓
      Gemini API
          ↓
        Gemini
          ↓
       Response

LangChain provides reusable components around the model:

    Application
         ↓
      LangChain
      ↙   ↓   ↘
   Prompt Model Tools
         ↓
        LLM

LangChain does not replace the LLM.

It provides abstractions that make it easier to build applications using LLMs.

---

# 2. LLM API vs LangChain

## Direct LLM API

The developer directly communicates with the model.

    Python
       ↓
    Gemini API
       ↓
    Gemini
       ↓
    Response

The developer manually handles prompts, tools, routing, and other application logic.

## LangChain

LangChain provides reusable building blocks.

    Application
         ↓
      LangChain
         ↓
    Gemini API
         ↓
       Gemini

Important distinction:

- LLM API = access to the model
- LangChain = framework for building applications around the model

# 5. Prompt Templates

Instead of hard-coding complete prompts, LangChain allows reusable templates.

Example:

    prompt = ChatPromptTemplate.from_template(
        "Explain {topic} in simple terms for a beginner."
    )

The variable can change dynamically.

For example:

    topic = "Docker"

produces:

    Explain Docker in simple terms for a beginner.

The same template can then be reused for:

- FastAPI
- Python
- Docker
- SQL
- Machine Learning
- etc.

---

# 6. Chains

A chain connects multiple operations together.

Basic chain:

    Prompt
       ↓
     Model
       ↓
    Output

In LangChain, this can be written as:

    chain = prompt | model

The `|` operator passes the output of the previous component into the next component.

---

# 7. Multi-Step Chain

The project contains a multi-step interview preparation workflow.

    Topic
      ↓
    Explanation
      ↓
    Interview Questions

The first model generates an explanation.

The second model receives the topic and explanation and generates interview questions.

This demonstrates how the output of one LLM operation can become the input to another operation.

---

# 8. LCEL

LCEL stands for LangChain Expression Language.

It provides a way to compose LangChain components using operators such as:

    |

Example:

    chain = prompt | model

A more complex workflow can combine multiple components.

---

# 9. RunnablePassthrough

`RunnablePassthrough` allows the original input to continue through a workflow unchanged.

Example:

    {
        "topic": RunnablePassthrough(),
        "explanation": prompt | model
    }

If the input is:

    FastAPI

then:

    topic → FastAPI

while:

    explanation → generated by Gemini

Both values can then be passed to the next prompt.

# 10. Tools

A tool is a function that an LLM application can use to interact with external systems or perform actions.

Example:

    @tool
    def calculate_sum(a: int, b: int) -> int:
        """Calculate the sum of two integers."""
        return a + b

The tool can then be invoked through LangChain.

Example:

    calculate_sum.invoke({
        "a": 10,
        "b": 20
    })

Result:

    30

Other possible tools include:

- GitHub API
- Weather API
- Database queries
- Search APIs
- Calculators
- File operations

# 11. LangGraph

LangGraph is a framework for building stateful, graph-based workflows for LLM applications.

Instead of thinking only in terms of a linear chain, LangGraph represents an application as a graph.

Example:

              START
                ↓
      Generate Explanation
                ↓
      Generate Questions
                ↓
               END

Each node performs a specific operation.

---

# 12. LangGraph State

LangGraph workflows use a shared state.

The project defines:

    class InterviewState(TypedDict):
        topic: str
        explanation: str
        questions: str

The state contains:

    topic
    explanation
    questions

Each node can read information from the state and return updates to it.

---

# 13. LangGraph Nodes

The project contains two nodes.

## Node 1 — Generate Explanation

    generate_explanation()

This node:

1. Reads the topic.
2. Sends it to Gemini.
3. Generates an explanation.
4. Stores the explanation in the state.

## Node 2 — Generate Questions

    generate_questions()

This node:

1. Reads the topic.
2. Reads the generated explanation.
3. Sends both to Gemini.
4. Generates interview questions.
5. Stores the questions in the state.

---

# 14. LangGraph Workflow

The graph is created using:

    graph = StateGraph(InterviewState)

Nodes are added:

    graph.add_node(
        "generate_explanation",
        generate_explanation
    )

    graph.add_node(
        "generate_questions",
        generate_questions
    )

Edges define the workflow:

    graph.add_edge(
        START,
        "generate_explanation"
    )

    graph.add_edge(
        "generate_explanation",
        "generate_questions"
    )

    graph.add_edge(
        "generate_questions",
        END
    )

Finally:

    app = graph.compile()

This compiles the graph into an executable application.

---

# 15. LangChain vs LangGraph

## LangChain

Useful for building LLM application components and workflows.

Example:

    Prompt → Model → Output

or:

    Prompt → Model → Prompt → Model

## LangGraph

Useful when workflows become more stateful and complex.

Example:

    START
      ↓
    Agent
     ↙ ↘
   Tool  Tool
     ↘ ↙
     Agent
       ↓
      END

LangGraph is particularly useful for:

- Stateful workflows
- Agents
- Tool usage
- Conditional routing
- Loops
- Multi-agent systems

# 21. Key Difference

The main conceptual difference learned during this project:

    LangChain
        ↓
    Components + Chains + Tools

    LangGraph
        ↓
    Stateful Graphs + Nodes + Edges + Workflows

LangChain helps build the components and workflows around LLMs.

LangGraph provides a graph-based approach for more complex, stateful workflows.
